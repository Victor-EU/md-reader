# By hand: WP 2.6, four themes and per-document reading settings

2026-09-09. Against the installed release build — `pnpm tauri build
--bundles app`, copied to `/Applications/MD Reader.app` — driven with
real keystrokes and a real mouse, with screenshots of the window.

## The setup

`wp26/report.md` — prose, a warning callout, a TypeScript fence and a
table, so a theme has somewhere to show its ink, its accent, its callout
colour and its code palette — and `wp26/notes.md`, a short document with
a Python fence, which is the one that follows the app throughout.

The settings file was replaced with one from the build before this one:
autosave, appearance, paper, family, size and measure, and no `theme`
field at all. That is the upgrade path, and it is check 1.

## What check 2 found

The four theme cards drew, and were selectable, and switching themes
worked — but the swatch strip on each card was a hairline. A `button`
is not an ordinary flex container in WebKit: it centres what is inside
it rather than stretching it, so a full-width strip left to `align-items`
came out with no width at all. Both `align-items: stretch` on the card
and `width: 100%` on the strip, and a comment saying why both. Rebuilt,
reinstalled, and the strips draw: four palettes side by side, plainly
different from each other.

Nothing else came up. The browser tests cover what a screenshot cannot:
that the same spans, not new ones, carry all four themes.

## Notes

- The measure is set in `ch`, so a document moved to the serif also gets
  a slightly wider column. That is the measure doing what it says —
  sixty-eight characters of the face it is set in — and it looked right.
- Check 13 needed the panel closed first. That is the AppleScript
  keystroke, not the app: a modifier-plus-punctuation keystroke sent
  while a panel has focus does not always reach the webview. Sent as a
  key code with the page focused, it worked every time.
