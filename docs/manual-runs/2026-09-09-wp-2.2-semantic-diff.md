# WP 2.2 by-hand check — the semantic diff engine

Date: 2026-09-09. macOS only; Windows is parked with no machine to run
it on. Scenario S4 end to end, against the four cases plan WP 2.2 names:
rewrapped paragraphs, moved sections, single-cell table edits, list
reorderings.

## How this was driven

The installed release build — `pnpm tauri build --bundles app`,
`/Applications/MD Reader.app`, launched with `open -a` on the document.
Real keys through System Events, real single clicks through `CGEvent`,
pictures of the app's own window through `screencapture`. The "agent" is
a pair of shell scripts that replace the file the way a tool does: a
temporary file moved over the target.

Document: `scratchpad/hand2/s4.md`, a seven-section field study with a
table and a bulleted list. Autosave off, so the unsaved edit S4 asks for
stays unsaved.

## S4, as the design words it

> The agent rewrites the file while it is open. The human has an unsaved
> edit in section 3. The agent rewrites sections 1 and 5. The buffer
> updates in place, the cursor and the unsaved edit are untouched, and
> sections 1 and 5 get a change marker in the gutter. The human presses
> a key to step through the changes, then "mark reviewed".

The agent's first write does four things at once, three of which a line
diff cannot tell apart.

| What the agent did | What the margin said |
|---|---|
| Reflowed the Background paragraph to a different wrap, and nothing else | **Nothing.** No mark, and the badge did not count it |
| Changed one cell of the Schedule table, `3-8` to `3-9` | That row, amber. Not the table, not the header |
| Swapped two bullets in Risks, word for word | The bullet that arrived, **blue**: it moved |
| Changed one word of the Notes paragraph, `client` to `sponsor` | That paragraph, amber |

The unsaved sentence in Method was where it was, with the cursor still
in it, and kept its own amber mark from before the write.

The status bar read `s4.md changed on disk · 5 changes merged in` beside
a badge of `Changes 4`. The two numbers are about different things and
both are right: the merge counts the hunks it brought over as bytes, and
three of the five were the reflow. The badge counts what the reader has
not looked at, and the reflow is not something to look at.

## Stepping, and marking reviewed

`⌥⌘G` walked the four in document order and put the cursor at the head of
each. `Mark Reviewed` from the palette cleared every mark and the badge,
and left the unsaved edit alone.

## The section that moved

The agent's second write moved the whole Scope section — heading and
paragraph, word for word — from the top of the document to the bottom.

| Check | Result |
|---|---|
| Where it arrived | Both blocks marked blue, `Changes 2` |
| Where it left | **Nothing.** No deletion notch between Background and Method |
| The rest of the document | Untouched, unmarked |

That is the rule the engine is built on: a move is one thing that
happened, so it is reported once, where it arrived.

## The save

`⌘S` wrote the merged document: the agent's reflow, the agent's cell,
the agent's reordering, and our sentence in Method. `Saved s4.md`, marks
cleared, dirty dot gone. The file on disk is 34 lines with nothing in it
that was not typed or written by one of us.

## The black paper

The change marks had no theme entry before this work package: three
hard-coded colours picked for white paper. They are now the annotation
palette's own `keep`, `attention`, `remove` and `rewrite`, which are the
same three values on the white paper and legible ones on the black.
Checked with an amber and a blue mark a few lines apart. Both read.

## What this run found

**A change mark is not drawn while live preview is rendering the block
it belongs to.** The changed table row was marked in Source mode, was
counted in the badge, and was reached by `⌥⌘G` — but in Edit mode, with
the table rendered, the margin beside it was empty. The mark appears the
moment the cursor enters the table and the source is revealed.

The cause is older than this work package: the marks are line
decorations, and CodeMirror does not render a line that a block widget
has replaced. WP 1.7 had the same hole; WP 2.2 makes it visible, because
a table row is now a block the engine reports on its own. The mechanisms
that would fix it — drawing the marks as a layer measured from
coordinates, or handing the change state to the widgets — are both a
rework of how a mark is drawn, which belongs with the Review mode of
WP 2.3 where change presentation is the subject.

Everything else in the run was as designed on the first pass.
