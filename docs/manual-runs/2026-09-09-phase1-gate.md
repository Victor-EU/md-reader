# Phase 1 gate, September 2026

Plan section 4, "Phase 1 gate". Run on 2026-09-09 by Claude (agent), macOS 15
(Darwin 24.5.0), Apple silicon, against commit `9a4b1de` plus the fixes this
run produced.

**The app under test was the installed release build**, not `tauri dev`:
`pnpm tauri build --bundles app`, copied to `/Applications/MD Reader.app`,
launched by double-clicking the file. Keystrokes were synthesized through
System Events, single clicks and drags through `CGEvent`, and every picture
is a `screencapture` of the app's own window.

The fixture is [gate-plan.md](gate-plan.md), copied into a throwaway git
repository so that `git diff` could answer the byte questions. The scenarios
were run in order; where one changed the file, it was restored before the
next.

## The five criteria

| Criterion | macOS | Windows |
|---|---|---|
| S1, S2, S3, S4, S8 by hand | **pass**, after three fixes below | not run |
| Corpus green with the Phase 1 action catalog, Chromium and WebKit | **pass** | not run |
| Identity invariant through the real save path over the corpus | **pass**, widened to both sets | n/a |
| Open to first paint under 100 ms at 1 MB | **pass**, 6× under | not run |
| Two weeks of the developer's own use, friction log reviewed | **not done** | — |

Windows is parked: there is no Windows machine. That is a standing decision,
not an oversight, and it makes the "on both platforms" half of the first and
fourth criteria unmet by choice.

**The gate is not passed.** Four of the five criteria are met on macOS. The
fifth cannot be done by an agent in an afternoon: it is two weeks of somebody
using the app for their own work.

## The scenarios

### S1. Read a plan

Double-clicked `plan.md` with the app closed. `LaunchServices` opened the
installed build; the process was up 246 ms later and the document was
rendered when the window appeared: headings, the task table, the Mermaid
diagram as a real flowchart, the callout with its header, `$E = mc^2$` as
KaTeX, `==highlights==` as a mark, the fenced JavaScript highlighted, the
checkboxes drawn.

Folding a section from the heading control worked. The outline listed all
five sections and clicking one scrolled to it and marked it current.

**Scrolling did not work from the keyboard.** Page Down, Space and the arrow
keys did nothing; the wheel and trackpad scrolled fine. Fixed (finding 1) and
re-run: one Page Down now moves a screen.

### S2. Mark up and hand back

Highlight, strikethrough, colour and comment all write exactly what design
4.3 says, and the comment leaves the cursor inside the empty note ready for
the reason. "Copy for AI" put the whole document plus an `Annotations (4):`
section on the clipboard, each entry with its anchor text and note.

**Highlighting a whole paragraph turned it into a heading.** Fixed
(finding 2) and re-run: the paragraph is now a highlighted paragraph.

The em dash in the annotations list arrives as `0xD1` if the shell reading
the clipboard is not UTF-8. That is `pbpaste` transcoding to Mac Roman, not
the app; the same trap caught the Phase 0 run.

### S3. Edit a table in place

Clicked the "Owner: Sam" cell in the rendered table, changed it to
"Owner: Lee", pressed Tab, changed `2026-09-15` to `2026-09-29`. The file on
disk afterwards:

```diff
-| Write the brief | Owner: Sam | 2026-09-15 |
+| Write the brief | Owner: Lee | 2026-09-29 |
```

One line, two cells, every other byte identical, and the file the same 1259
bytes it started as. Nothing to fix.

### S4. The agent rewrites the file while it is open

Autosave off, an unsaved edit typed into section 3, then a script rewrote
sections 1 and 5 on disk. The status bar said "plan.md changed on disk · 2
changes merged in". Sections 1 and 5 carried change marks, sections 2, 3 and
4 did not, the unsaved edit was untouched, and the cursor moved from Ln 27 to
Ln 28 — following its own text, which is what the merge is for. Saving wrote
all three: both of the agent's sections and the reader's sentence.

**There was no way to step through the changes**, which is S4's last clause;
the palette answered "Nothing matches" to "change". Fixed (finding 3) and
re-run: from the top of the document, `⌥⌘G` went to Ln 10, then Ln 46, then
back to Ln 10.

"Mark Reviewed" cleared the marks and the badge and said so.

### S8. Write a brief for the AI

Cmd+N, a heading and three bullets — the list continued itself after the
first `-` — then Cmd+S. One dialog, pre-filled `Cut the sprint to three
weeks`, with the location already set to the folder of the open document. The
file landed there with exactly what was typed. No template.

## What was found

The findings and what was done about each are in
[the ADR](../adr/0018-phase-1-gate.md). Three were fixed and re-verified
against a rebuilt release bundle; three were left, with reasons.

Two of those three were taken up later the same day: the mode of a new file
and whether comment text is words. Both are fixed, and both were verified
the same way, against a bundle rebuilt and installed over the one this run
used -- a new document saves as `-rw-r--r--`, and a five-word note left the
count at 49 while one word of prose moved it to 50. The suite is 1268 tests
over 90 files and 93 in `cargo test` as those fixes landed. Windows is the
one finding still left, by the standing decision recorded above.

## The measured criteria

`pnpm test`: 1259 tests over 90 files, Chromium and WebKit. `cargo test
--workspace`: 91. The round-trip corpus runs 16 actions over 426 documents in
the Node runner and the cell editor and an IME composition over 24 in both
engines.

`crates/core/tests/corpus_identity.rs` covered only `corpus/adversarial`. The
criterion says "over the corpus", so it now reads both sets: 225 committed
files, opened and saved through the real Rust path, byte-identical, and one
edit changing only its own bytes.

First paint at 1 MB on this machine, `pnpm bench`:

| Engine | 100 KB | 1 MB | Budget |
|---|---|---|---|
| Chromium | 12 ms | 13.9 ms | 100 ms |
| WebKit | 16 ms | 17 ms | 100 ms |

Keystroke p95 at 1 MB, worst of the three positions: 9.7 ms on Chromium and
13 ms on WebKit, both in the middle of the document. The
plan wants a pinned bench machine; this is a developer laptop, so the numbers
are indicative of the margin rather than a regression baseline.

## What the harness got wrong

Recorded because anyone repeating this by script will hit the same walls.

- **`osascript` key codes with modifiers are unreliable in sequence.** Runs
  of `Cmd+Down`, `Shift+Up`, `Shift+Cmd+Left` produced selections nothing
  like the intended one, twice. Drag-selection through `CGEvent` was exact
  every time. Clicks must carry click count 1 — System Events' `click at`
  reaches WKWebView as a multi-click, which was already known from Phase 0.
- **Two bundles with the same identifier confuse `LaunchServices`.** A stale
  debug bundle in `target/` was preferred for `.md` over the installed app,
  and launching it rewrote a generated source file (finding 4).
- `/Applications/MD Reader.app` was a build from 2026-09-07, the WP 0.1
  skeleton. The old bundle is kept in the session scratchpad.
