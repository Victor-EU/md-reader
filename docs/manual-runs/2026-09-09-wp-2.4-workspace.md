# By hand: WP 2.4, the folder workspace

2026-09-09. Scenario S6 end to end against the installed release build —
`pnpm tauri build --bundles app`, copied to `/Applications/MD Reader.app`
— driven with real keystrokes and clicks, with window screenshots at
every step. Not `tauri dev`, and not a test harness.

## The folder

Twelve markdown files an "agent" had produced, in the shape the scenario
describes: `README.md`, `findings.md`, `method.md`, `questions.md`,
`glossary.md` and `notes.md` at the top, four papers in `sources/`, two
abandoned openings in `drafts/`. Three more files were there to be *not*
seen: a `.gitignore` naming `build/` and `*.log`, a `build/index.html`,
and a `run.log`.

## Opening the folder

The blank window offers **New File** and **Open Folder…** beneath its
one sentence. Open Folder… brings up the OS panel asking for a folder;
Cmd+Shift+G, the path, Enter, Open.

The sidebar came up on **FILES** with the folder's name and its twelve
files: `drafts` and `sources` first, then the six at the top level in
alphabetical order, `README.md` last because the sort ignores case. The
status bar said `Working in research`.

`.gitignore` did what it says: no `build/`, no `run.log`, and the
`.gitignore` itself is a dotted name and not shown either.

Clicking `sources` unfolded it — four papers, indented, the row marked
as the selection. Clicking `sorqvist-2010.md` opened it in a tab in Read
mode, with the breadcrumb reading
`… › scratchpad › research › sources › sorqvist-2010.md`.

## Cmd+P

Typed `drseco`. One row: **intro-second-try.md**, detail `drafts`, with
`seco` underlined in the name. The `dr` had matched in the directory,
which the row does not underline because there is nothing there to
underline — the score used the whole path, the highlight is only what
falls in the name. Enter opened it.

## Cmd+Shift+F

The key opened the sidebar on FILES and put the keyboard in the search
field. Typing `cat` filled the panel while the walk was still going:

```
3 in 3 files
hughes-2013.md   sources
   3  … content. The cat
sorqvist-2010.md sources
   6  > The cat sat on the mat is e…
marsh-2018.md    sources
   3  Repli[cat]ion with a larger sa…
```

Then the same search with `the cat is in the log` appended to `run.log`
and to `build/index.html`. Still **3 in 3 files**: the search walks the
folder through the same `ignore` walker the tree does, so a file the
tree will not show is a file the search will not read.

Clicking the `marsh-2018.md` result opened it in a new tab at the line.
Read mode has no cursor, so the check is what Edit does with it:
`⌥⌘E`, and the selection is on the three characters `cat` inside
`Replication` — the column survived the trip.

## New file

With `README.md` selected in the tree, **New** made `Untitled.md` at the
top level and turned its row into a text field with the name selected
and the keyboard in it. The status bar said
`Untitled.md · name it and press Enter`.

Typed `brief.md`, Enter. The file moved into place in the tree, opened
as a tab, and — being empty, and having just been made to write in —
opened in Edit rather than Read.

## The watch

With the window open and `sources` unfolded, a shell wrote
`sources/kjellberg-2008.md` into the folder. It appeared in the tree, in
its sorted place, with nothing pressed.

The same command appended to `run.log` and to `build/index.html`.
Nothing moved: the folder watch carries the root's ignore rules, so a
build writing into an ignored folder does not wake the tree.

## After a quit

`⌘Q`, then launch again. The folder came back with its tree, the sidebar
on FILES, and all five tabs, active tab included:
`Picked up where you left off · 5 tabs`. Unfolded folders do not come
back unfolded — the tree reads a level when it is opened, and the
session carries the folder rather than the shape it was left in.

## What the run changed

Two things were wrong enough to fix and check again:

- **A match beyond the width of the panel was invisible.** The engine
  cuts a line only when it is longer than 300 characters; a 70-character
  line with the match at the end fitted the payload and not the row, so
  the row showed the start of the line and the highlight was off the
  end. The panel now drops the front of the line when the match is more
  than sixteen characters in, with a leading ellipsis, which is what the
  engine already does for the very long ones.
- **A new file opened in Read mode.** It is empty and it was made to be
  written in; it opens in Edit now, for the same reason Cmd+N does.
- **A file made this way was written back without a trailing newline.**
  Autosave restores the form the file was read in, and a file with no
  bytes in it was read as one with no trailing newline — so `# Outline`
  landed on disk without one, and would have for the rest of the file's
  life. An empty file has no stored form to preserve, so it now takes
  the app's own, which is the same one Cmd+N gives a new document.

## What the run found and did not fix

Typing into any document and waiting for autosave puts `Changes 1` in
the toolbar and a mark in the margin, beside the reader's own words.
Design 4.1 says the badge is for "unreviewed external changes"; this is
the reader's own typing.

It is not this work package's: an autosave deliberately does not mark
what an agent wrote as read (the timer firing is not the reader reading
it), so `reviewed` stays where it was, and the diff that follows the
save sees the reader's own edits as well as anybody else's. Making the
baseline follow the reader's edits while staying behind everything else
needs the mapping between baseline and buffer that the change records
carry, which is a piece of work rather than a flag. Recorded as a
separate task; the fixture folder and the steps above reproduce it in
one keystroke.
