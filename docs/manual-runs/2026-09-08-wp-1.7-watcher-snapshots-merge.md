# WP 1.7 by-hand check — watcher, snapshots, merge

Date: 2026-09-08. Build: the real desktop window under `pnpm tauri dev` —
WKWebView, the OS open panel, a real file on a real filesystem. This is
the work package where that matters most: every scenario below is a write
by a process that has never heard of the app, made with `python3` or `mv`
or `rm` from a shell beside it.

The document is in the session scratchpad: four sections, one the reader
edits by hand and does not save, two the other process rewrites, one that
never moves.

## A write while the buffer is clean

| Check | Result |
|---|---|
| Rewrite one paragraph, Read mode open on the file | The page updates in place; no reload, no flash |
| Status line | `wp17.md changed on disk · 1 change merged in` |
| Changes badge | Appears, reading `Changes 1` |
| Saved state | Still `Saved`: the buffer matches the file |
| Three writes inside a second | One report, not three |

## S4: a write while the buffer is dirty

The reader's cursor is at the end of a sentence they have typed in
section two and not saved. Another process rewrites sections one and four.

| Check | Result |
|---|---|
| The unsaved sentence | Still there, word for word |
| The cursor | Still at the end of it |
| Sections one and four | Both hold the other process's version |
| Section three | Untouched |
| Status line | `s4.md changed on disk · 2 changes merged in` |
| Badge | `Changes 3` — their two and the reader's one |
| Status bar | `Unsaved changes`, as it was before the write |
| Dialogs | None, anywhere in this |

## A conflict

Same again, and then the other process rewrites the very line the reader
is editing.

| Check | Result |
|---|---|
| The buffer | Keeps the reader's version of that line |
| Status line | `s4.md changed on disk · 1 conflicting change set aside, your version kept` |
| Everything else | Undisturbed |
| What was set aside | In the history: an `external` snapshot, read back through `read_snapshot`, holding their line verbatim |

The widget that offers both versions is WP 2.1. What Phase 1 owes is that
nothing is lost, and nothing was.

## The file itself

| Check | Result |
|---|---|
| `rm` the file under the tab | Buffer stays; status bar cell reads `File is gone`; message says `wp17.md is no longer on disk · saving writes it again` |
| Cmd+S after that | The file is written again, byte for byte, and the cell goes back to `Saved` |
| `mv` the file to another name | The tab label and the breadcrumb both follow; status says `wp17.md is now renamed-by-hand.md` |
| A write to the renamed file | Still watched: `renamed-by-hand.md changed on disk · 1 change merged in` |
| Our own Cmd+S | No report at all — the write is recognized as ours by its hash |

## Change marks and the badge

| Check | Result |
|---|---|
| Where the marks are | An amber bar in the left margin of the measure, beside the line |
| A run that wraps over two rows | The bar covers both |
| `Mark Reviewed` from the palette | Marks and badge both clear; status says `Marked as reviewed` |
| After marking, typing again | The badge comes back for what was typed after it |

## The history store

Read with `sqlite3` and through the app's own `read_snapshot`:

| Check | Result |
|---|---|
| `schema_version` | One row, version 1 |
| Rows | One per open, one per save, one per external write, with `user` and `external` authors |
| Repeated content | Nine snapshots, five blobs: the four that share content share one blob |
| Round trip | Every row's content read back through zstd exactly as it was written |
| Where it lives | `~/Library/Application Support/io.github.victor-eu.mdreader/history` |

## Found and fixed during the pass

- **The change marks were in a gutter, a third of a screen from the text.**
  A `CodeMirror` gutter sits at the left edge of the editor, and the
  measure is centred in the pane, so the first version drew the bar 430
  points from the line it was about. Now they are line decorations in the
  padding the measure already has. ADR 0012 records why, including why
  centring the gutter with the text was the wrong fix: it would shift the
  text column between Read and Edit.

## Not checked by hand

- **Drag and drop from Finder**, still outstanding since WP 1.3: a real
  Finder drag cannot be synthesized, and the webview's own drop handler
  is the code under test.
- **Windows.** Parked; no machine.
- **A rename out of every watched folder.** The code path is the same one
  a delete takes, and the delete case is checked above.

## Notes on the method

Two false alarms, both mine and both worth writing down:

- A stray `Cmd+Shift+H` in a script (key code 4 is `h`, not `End`) applied
  a highlight and then typed over the selection. The document that came
  out looked like a merge bug for a minute.
- Creating a scratch test file under `crates/core` made `tauri dev`
  rebuild and restart the app, which closed the tab mid-check. Session
  restore is WP 1.8; until then, nothing that touches a Rust file can run
  while a by-hand pass is open.
