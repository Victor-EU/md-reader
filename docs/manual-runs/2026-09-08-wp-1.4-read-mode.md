# WP 1.4 by-hand check — Read mode

Date: 2026-09-08. Build: the app's own frontend from `pnpm tauri dev`'s Vite
server, driven in Chromium at 1280×720, light and dark. Documents were
typed into an untitled tab, so nothing here needed the file dialogs.

The desktop window itself could not be used: the machine's screen was
locked for the whole session, and a locked macOS session presents no
windows — the app process ran with none. What that costs is named at the
bottom. Everything below is the same Svelte and TypeScript the packaged app
runs, over the same renderer, in a browser instead of WKWebView.

| Check | Result |
|---|---|
| Open a document | Opens in Read, the Read segment is pressed, Edit and Source are one shortcut away |
| Frontmatter | Rendered as the YAML it is, dimmed, in its own block |
| Prose | Emphasis, strong, inline code, link, `==highlight==` and `~~strikethrough~~` all rendered, no marks left in the text |
| Inline and block math | KaTeX, both; the block one centred |
| Python fence | Shiki, with the language's own colours |
| Mermaid fence | Diagram rendered, replacing the source |
| Task list | Checkboxes, disabled, the done one checked |
| Table | Alignments from the delimiter row, striped rows, its own scroll container |
| Callout | Type colour and title, body below |
| Comment | Not in the page |
| Click a word | Switches to Edit with the cursor inside that word (`paragraph`, offset 16 of the line) and the paragraph in the same place on screen |
| Cmd+Alt+R | Back to Read, at the place the editor was |
| Fold a heading | Its section hides down to the next heading of the same level; the heading and everything after the section stay |

Fixed while checking, before the commit:

- Fenced code was wrapped in Shiki's spans but showed no colour. With two
  themes and `defaultColor: false`, Shiki writes `--shiki-light` and
  `--shiki-dark` onto each span and leaves the choice to the page; the
  stylesheet had no rule to turn them into `color`. The rule is in
  `app.css`, and `enhance.browser.test.ts` now asserts that a token's
  computed colour differs from the block's, so the stylesheet is part of
  what the test covers.
- Folding a section un-hid the comments. Folding assigned `el.hidden` on
  every top-level block, which cleared the `hidden` the renderer puts on a
  comment. Folding now uses a class of its own, and the read-mode test
  keeps a comment in its fixture and asserts it stays hidden.

## Not checked by hand

- **Opening a file from disk in Read mode.** The IPC path is the one WP 1.3
  checked by hand, and the document store tests cover open-into-Read, but
  the two have not been through the packaged app together.
- **The opener actually opening a browser.** What is verified is that the
  webview does not navigate and that the URL reaches `openExternal`. The
  Tauri side is the plugin's own `openUrl` with the capability narrowed to
  `allow-open-url`.
- **WKWebView.** The automated tests run in headless WebKit, which is the
  same engine, but not in the app's own webview.
- **Dragging a file from Finder**, still outstanding from WP 1.3.

All four need the desktop window, so they are the first thing to do in the
next session with an unlocked screen.
