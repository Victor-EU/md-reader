# WP 2.1 by-hand check — the conflict widget

Date: 2026-09-09. macOS only; Windows is parked with no machine to run
it on. Scenario S5 end to end, plus the two states around it that the
plan asks for: the save that is held, and the timer that is held with it.

## How this was driven

The installed release build — `pnpm tauri build --bundles app`,
`/Applications/MD Reader.app`, launched with `open -a` on the document.
Real keys through System Events, real single clicks through `CGEvent`,
pictures of the app's own window through `screencapture`. The "agent" is
a shell script that writes the file the way a tool that replaces a file
does: a temporary file moved over the target.

Document: `scratchpad/hand/s5.md`, a four-section plan.

## S5, as the design words it

> Same as S4, but the agent also rewrote the paragraph the human is
> editing. That paragraph shows both versions inline with "keep mine"
> and "take theirs". Nothing else is blocked.

| Step | What happened |
|---|---|
| Unsaved edit typed into the Method paragraph | Change mark beside the line, dirty dot on the tab, `Unsaved changes` |
| The agent rewrites Background **and** Method | Background took their rewrite silently, with a change mark |
| The same write, on the Method paragraph | `MINE` band over our line, `THEIRS` panel under it, `Keep mine` and `Take theirs` |
| The status bar | `Save held` · `1 conflict` (underlined: it is a button) |
| The message | `s5.md changed on disk · 1 change merged in · 1 conflict to settle` |
| Everything else | Scrolls, reads, edits. Only the write of this document stopped |

## The save, held

| Check | Result |
|---|---|
| Cmd+S with the question open | `s5.md: 1 conflict to settle before it can be saved` |
| The file on disk after that | Still the agent's version. Our line was not written over it |
| `Take theirs` | Line became theirs, panel gone, `Save held` gone, buffer clean |
| Cmd+Z | Both came back: our line **and** the question |
| `Keep mine`, then Cmd+S | Wrote the merged document: their Background, our Method |

## The same with autosave on

Autosave was switched off for the run above, so the unsaved edit would
sit still. Switched back on, the write was raced against the 800 ms
timer instead — a keystroke, then the agent's write inside the window.

| Check | Result |
|---|---|
| The timer, with the question open | Did not write. File on disk stayed the agent's |
| The message | Stayed on `s5.md changed on disk · 1 conflict to settle` |
| `Keep mine` | `Kept your version`, and the timer wrote our line a moment later |

## Read mode

| Check | Result |
|---|---|
| A write that conflicts while reading | Page unchanged, bar reads `Save held` · `1 conflict` |
| Pressing the `1 conflict` cell | Switched to Edit with the widget in front |
| Source mode | Same widget, in the mono face. It is not a decoration of one projection |

## What this run changed

Two things, both found here and neither by a test.

**The widget's own buttons said nothing.** They dispatch straight to the
editor rather than through the shell, so settling from the panel left
the bar still reading `1 conflict to settle before it can be saved` --
about a question that had just been answered. The line is now written
where both roads meet, in `applyTransactions`, off the transaction's own
user event. `conflict.browser.test.ts` has it now.

**An autosave already on the clock still fired.** A conflict that lands
between a keystroke and the timer it set does not cancel that timer: it
fired, was refused inside `writeNow`, and replaced the line that said
what had arrived with one about a save nobody asked for. Two changes:
`scheduleAutosave` clears the pending timer before it decides whether to
set another, and a refusal from the timer says nothing, because the bar
already reads `Save held` beside the count. The test pins the message;
the cancellation itself is only visible as a `Saving…` flicker, which is
why it was found by hand.
