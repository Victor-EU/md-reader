# WP 1.11 by-hand check — autosave and new files

Date: 2026-09-08. macOS only; Windows is parked with no machine to run
it on.

## How this was driven, and what that costs

The window could not be driven by hand. `screencapture` returns the
desktop picture with no windows in it, and System Events reports zero
windows for every process including Finder — which is what macOS does
when the shell has neither Screen Recording nor Accessibility
permission. So there was no way to press a key in the app or to
photograph it.

What was used instead, and what each is worth:

- **The real app, driving itself.** `pnpm tauri dev`, with a temporary
  block appended to `main.ts` that opened the scratch files, typed into
  the real editor, and logged what it found — reverted before the
  commit. Everything below the line "against the real app" ran through
  the real IPC, the real Rust save path, the real history store and real
  files on disk in a real WKWebView. What it cannot show is the keyboard
  and the menus: every command was called rather than pressed.
- **The scratch harness, for the pictures.** The real components over
  the fake IPC, served by Vite and photographed with Playwright in
  Chromium. Real stylesheet, real components, not WKWebView. Deleted
  afterwards.

Files: `notes/brief.md`, `notes/other.md`, and `notes/big.md` — 335 KB,
4000 paragraphs, so a partial write would be obvious.

## Against the real app

| Check | Result |
|---|---|
| 400 ms after typing stops | File unchanged |
| 1100 ms after typing stops | `- Three` on disk, buffer clean |
| The status line after an autosave | Still `brief.md · UTF-8 · LF` — autosave says nothing |
| A burst of four words, 120 ms apart | One write, after the burst |
| The trailing newline the file was opened with | Restored on every autosave |
| Typing, then opening another tab | `written on the way out` on disk within 300 ms |
| Autosave off, 1200 ms after typing | File unchanged, buffer dirty |
| Autosave off, then Save | Written |
| Cmd+N, a heading, then Save | Panel opened on `…/notes/Team brief.md` |
| The window closing straight after typing | See below |
| `kill -9` during a run of autosaves | See below |

### The close

Instrumented inside the `beforeCloseEvent` handler, so this is not the
debounce firing first:

```
beforeClose dirty=true  disk="he timer is watched.\n\n- One\n- Two\n"
afterFlush              disk="\ntyped and then the window closed\n"
```

The buffer was dirty and the file did not have the text when the close
began; `flushPending` wrote it, and Rust held the close open until it
had. The app then exited.

`window.close()` is not in the app's Tauri capabilities — the app never
calls it — so `core:window:allow-close` was added for this check and
removed afterwards.

### The kill

The manual protocol's kill-mid-autosave check (build plan 7.5). Typing a
line a second into `big.md`, so an autosave landed between every line,
then `kill -9`:

- The file is 335,229 bytes and ends with a complete line and a newline.
- All 52 typed lines are present and whole.
- No temp file left behind in the folder.

The first attempt at this typed every 200 ms with no pause and wrote
**nothing at all** — the debounce is plain, so an unbroken run of typing
is never autosaved. That is design 6.6 as written, and it is recorded in
ADR 0015 rather than fixed here.

### The history

52 autosaves of `big.md` inside one minute:

```
id                      author    timestamp_ms   byte_len
1788900456047-000035    user      …456047        334822
1788900512137-000036    autosave  …512137        335229
```

One row for the run, holding the newest content, plus the `user` row
from opening the file. Without coalescing that would have been 52 rows
and 52 compressed copies. `brief.md`, across several sessions, shows
five autosave rows — a fresh one each time a run was broken by a restart
or by a save made by hand.

## What was found and fixed

- **An autosave cleared the Changes badge.** `markSaved` recorded every
  save as read, so a write from an agent stopped being marked 800 ms
  after the reader typed anything. Fixed: a save on a timer records the
  file, not a reading. ADR 0015.
- **The history would have filled with one version per pause.** Found by
  arithmetic before the run and confirmed by it. Fixed in the store; see
  above.
- **`Unsaved changes` on a document with no file.** It claims a saved
  version exists. Now `Not saved yet`.
- **The blank window offered a new file in words with no way to take it
  up.** A button, running the same command as Cmd+N.

## What was not checked

- **The keyboard and the menus.** Cmd+N, Cmd+S, Cmd+Q and the palette
  were called rather than pressed. The command registry that binds them
  is covered by its own tests, and was not touched by this package.
- **A real blur.** Switching applications by hand needs the window. The
  handler is one line in `App.svelte` calling `flushAutosave`, which the
  close path exercises.
- **WKWebView for the pictures.** The automated browser tests do run on
  WebKit, including all 19 autosave tests.
- **Windows.** Parked.

## One oddity, recorded

An early run left a zero-byte `Autosave by hand.md` in the scratch
folder. That run had two native save panels open at once, because a Vite
reload restarted the script while the first panel was still up, and its
`typeInto` had typed into the previous document's view — so the document
being saved really was empty. With the harness corrected, the panel was
offered `…/notes/Team brief.md` and no file was created. Nothing was
overwritten and no document lost text, so this is recorded as a harness
artifact; the name on that file is not fully explained.
