# ADR 0015: WP 1.11 Autosave and new files

Status: accepted, 2026-09-08. Covers autosave and its off switch, the
first save of a document nobody has named, and the two things autosave
turned out to break on its way in: the history, and the Changes badge.

## Autosave is a property of a document, not of the window

Design 6.6 asks for one write 800 ms after the last keystroke, and again
on blur, on tab switch, and on window close. Those four moments have one
thing in common — the reader has stopped putting words into this
document — so they all run the same call, `write(doc, { auto: true })`,
and the only difference between them is what cancels the timer first.

The timer is per document rather than per window. Two tabs on one
document share it, because they share the buffer; two documents each
have their own, because a background document that took an external
write is not waiting on the foreground one's typing.

`activate` treats two tabs on the same document as not leaving it. That
is not an optimisation: writing the file because the reader looked at
their own second view of it would be a save nobody asked for, and one
more version in the history for nothing.

## What autosave will not do

**It will not name a file.** A document with no path is skipped
entirely — no dialog, no write. The session already carries an untitled
buffer whole (WP 1.8), so nothing is at risk, and a save panel that
opened by itself 800 ms after somebody started typing would be the
worst dialog in the app. The first save is the reader's, and from then
on the document is autosaved like any other.

**It will not write a file it cannot write.** A read-only encoding
(WP 1.1) is skipped, with the same message Save gives.

**It will not fire while typing continues.** The debounce is plain: each
keystroke resets it, so an unbroken run of typing with no pause is never
autosaved until the reader leaves or the window closes. That is what
design 6.6 asks for, and the by-hand pass confirmed it — typing every
200 ms for a minute wrote nothing. People pause between words far more
often than they think; a maximum wait would be a different decision from
the one the design made, and this is not the package to make it in.

## Closing a tab writes it

WP 1.3 promised that closing a dirty tab keeps the buffer and says so,
because there is no dialog to ask. With autosave on, the promise is
better kept by writing the file: closing is the strongest form of
leaving, and a reader who closes a tab after typing does not mean
"discard". So `close` writes first and then says `Closed brief.md`
rather than `Closed brief.md with unsaved changes`. With autosave off,
the old sentence and the old promise stand, and reopening the tab is
still how the buffer comes back.

## One write of a file at a time

Two overlapping writes of one document would race: the second reads its
expected hash before the first has changed it, then arrives to find a
file it does not recognise — our own save, reported back to us as
somebody else's, complete with a merge and a spurious snapshot. So
`write` chains per document: a write that finds one running waits for
it. The chain is at most two deep in practice, because the only two
writers are a debounced timer and a keystroke.

The retry after a hash mismatch calls `writeNow` directly rather than
`write`, or it would queue behind the write it is the retry for.

## The save panel opens on a name, not on `Untitled 3`

Scenario S8 is a person pressing Cmd+N, typing a heading and three
bullets, and saving. Design 4.5 says the panel proposes a name from the
first heading, in the open folder or the folder of the active document.

The heading comes from the same renderer Read mode uses, so
`# The **fast** path` arrives as `The fast path` with no markup left to
strip, and a `#` inside a fence is not a heading at all.

`naming.ts` turns that into a file name both platforms will take, which
is most of the work: path separators and the characters Windows refuses
become spaces; control characters, zero-width joiners and direction
marks go, because a name nobody can retype is not a name; a leading dot
would hide the file on Unix and a trailing dot or space is one Windows
quietly trims; the device names — `CON`, `NUL`, `LPT1` — are given up on
rather than mangled; and it is cut at 60 characters on a word boundary,
counting characters so an emoji is never halved. Spaces and case are
kept. This is the reader's own title, not a slug.

There is no folder workspace until WP 2.4, so "the open folder" is the
folder of the nearest document this window already has open, and failing
that the last file it opened.

## Two things autosave broke, and what was done about them

### The history would have become a log of keystrokes

WP 1.7 takes a snapshot when a file is opened, when somebody else writes
it, and when the app saves it. That was reasonable when a save was a
keystroke. With autosave it is a version per pause in typing: the
by-hand pass typed for a minute in a 335 KB document and would have
recorded 52 versions, each a compressed copy — around 17 MB for a
minute's work, and a history nobody can read.

So the store coalesces. `SnapshotAuthor` gains a fourth value,
`Autosave`, and a snapshot updates the newest row instead of following
it when both are autosaves and that row is younger than `COALESCE_MS`
(two minutes). The row keeps the time the run started and takes the
newest content: going back to it is going back to the pause before that
run began, which is the moment a reader would ask for. The same minute
of typing is now one row. Nothing ever coalesces onto a version somebody
asked for, so opening a file and saving it by hand are still exactly
where they were, and a save by hand in the middle of a run starts a
fresh row after it.

The blob a coalesced row stops pointing at is left for `collect_blobs`,
which already runs at every launch.

This is a change to WP 1.7's package, made here because autosave is what
breaks it. An older store reads unchanged: an unknown author name reads
as `User`, and the worst that does is decline to coalesce.

### A timer is not a reader

`markSaved` used to record a save as read: base and reviewed both became
the written text, so the Changes badge went to zero. With autosave that
meant an agent's write, which design 4.4 says stays marked until the
reader has looked at it, would be cleared by a clock 800 ms after they
typed a character somewhere else.

`markSaved` now takes `seen`. A save the reader asked for still counts —
they were here, they pressed the key. A save on a timer records the file
and leaves the marks where they are.

## The status bar says which world it is in

Design 4.1 lists autosave state as a status bar field. With autosave on,
the field that was already there is the autosave state: `Saving…`,
`Saved`, and `Unsaved changes` for the second before the timer fires. It
is when autosave is off that a reader needs telling why nothing is
happening, so `Autosave off` is a cell of its own, shown only then.

A document with no file now reads `Not saved yet` whether or not it is
dirty. `Unsaved changes` claims there is a saved version to be unsaved
against, and for an untitled document there is not.

## Turning it on writes what is already dirty

Off is off: the timers are cancelled and the dirty dot comes back. On
is a decision that the disk should be current, so it writes what is
dirty now rather than waiting for the next keystroke to catch up. A
document that sat dirty while the switch said "on" would be the setting
telling a lie about itself.

## What is not here

- **A maximum wait.** See above; the debounce is the design's.
- **A save button.** Cmd+S and the palette, as before.
- **Sidebar "New file".** It arrives with the sidebar in WP 2.4. The
  blank window grew a `New File` button instead, because it already
  offered one in words and Cmd+N was the only way to take it up.
- **Held saves for conflict regions.** There are no conflict regions in
  Phase 1; they and the save they hold are WP 2.1.
