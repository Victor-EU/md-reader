# 0016 — WP 1.10: editing conveniences

Date: 2026-09-09. Status: accepted.

## Context

Design 4.5 lists the conveniences that make a text editor feel like a
document rather than a text box: the four inline marks, list behaviour
on Enter and Tab, a checkbox you can click, paste that understands what
is on the clipboard, find and replace, and the webview's spell check.
Three of them arrived with the editing core in WP 0.3 — Enter, Tab and
Shift-Tab, and the checkbox widget in Edit mode. This package is the
rest, and the corpus actions for all of it.

## Decisions

### The marks read the run of asterisks, not the two characters either side

`toggleWrapEdit` in `annotate.ts` asks "are the characters right here the
marker" and that is the right question for `==` and `~~`, which do not
nest. It is the wrong question for emphasis. `**word**` has a `*` either
side of the word, so the same test reads bold as italic and Cmd+I would
halve it.

`markEdit` counts the run of marker characters on each side instead and
takes the smaller. Bold is a run of two or more, italic is an odd run,
and a code span is any run at all. So Cmd+I on `**word**` writes
`***word***`, Cmd+I on `***word***` writes `**word**`, and Cmd+B on
`***word***` leaves `*word*` — which is what the reader means each time.

### A mark applies to the word under the cursor, and never to whitespace

Design 4.5 says a mark applied to a word wraps the word, so an empty
selection expands through `state.wordAt`. Two edges came out of using it
by hand:

- The cursor stays a cursor. Wrapping the word around a cursor and then
  selecting the word would leave the reader having to click back into it;
  the cursor keeps its place, shifted by the marker.
- A selection is trimmed to its non-whitespace core, and a selection of
  nothing but whitespace is refused. A drag past the end of a line takes
  the line break with it, and `**` either side of a line break is four
  asterisks the reader then has to delete. This was found by hand, not by
  a test.

A cursor with no word around it is the one case where an empty pair is
written: `**|**`, ready to type into. That is what every editor does and
what reaching for Cmd+B before writing the word means.

### `Mod-i` had to be taken out of CodeMirror's keymap, not shadowed

`defaultKeymap` binds `Mod-i` to `selectParentSyntax` with
`preventDefault: true`. The editor's keymap sits on the content element
and the shell's sits on the window, so the editor sees the key first and
`preventDefault` stops it there: Cmd+I selected the enclosing block and
italic never ran. Shadowing cannot fix that — the binding has to go.

`state.ts` filters it out, and `commands.test.ts` in the app now walks
every key the editor claims and fails if the shell claims it too. The
collision was silent, which is the reason for the test rather than the
one-line fix.

### HTML to markdown is ours, and writes only the dialect

The clipboard's `text/html` is converted by `packages/markdown/src/import`
rather than by a general converter. Design 5.4 says the app only ever
writes the constructs of design 5, and a general converter emits setext
headings, reference links, `_italic_`, and raw HTML passthrough — none of
which this app writes. What it does not recognise is unwrapped to the
text inside it, which is the reading a browser would give it anyway.

The four whitelisted tags markdown has no syntax for — `sub`, `sup`,
`kbd`, `u` — are written back as themselves, because that is how the
dialect spells them.

### Rich text is taken only when there is formatting to keep

Every browser puts `text/html` on the clipboard even for a line of prose
copied out of a text editor, wrapped in a `meta` and a styled `span`.
Converting that would only escape the writer's own asterisks. So the HTML
flavour is used only when the fragment holds a tag markdown has a word
for; otherwise the editor's own exact paste runs.

The order a paste is decided in is the whole design: images first, then a
URL over a selection, then rich text, then the plain paste.

### Rust decides where an image goes, and whether it is one

`store_asset` writes into `assets/` beside the document. Two rules keep
the folder honest. The bytes have to be an image by magic number — the
extension a clipboard or a file name claims is never trusted, so a paste
cannot drop an arbitrary file next to somebody's notes. And a name
already taken by the same bytes is reused rather than duplicated, so
pasting one screenshot into three places leaves one file.

Pasted bytes cross the bridge base64-encoded: one string, rather than the
JSON array of a million numbers the generated bindings would otherwise
produce for every screenshot. A dropped image never crosses at all — Rust
has the path and copies the file.

### Find and replace: their state machine, our bar

`@codemirror/search` holds the query and does the stepping and replacing.
The bar itself is a Svelte component in the window chrome, because that
is where this app's furniture lives. The one piece that had to be written
here is the highlighter: theirs draws matches only while their own panel
is open, and there is no such panel.

Opening find in Read mode switches to Edit first. Matches are drawn by an
editor extension and replace needs somewhere to write, so the mode that
can do neither is not the mode to be in.

### Indent and outdent are corpus actions that check invariant A alone

Adding Tab and Shift-Tab to the corpus showed that indentation does not
satisfy invariant B. Making an item a child of the one above it can join
the list to the list after it, which is a change to the tree outside the
block the bytes landed in. That is what indentation is for, so the
invariant is wrong for it rather than the command being wrong.

`ActionPlan.structural` says so, and those two actions check exactness
over the whole corpus and locality nowhere. They also carry a
`minChecked` floor of 60 files rather than the usual quarter of the
corpus: an outdent needs a nested list, and most prose has none.

Rich-text paste did not become a corpus action. Its byte change is one
replacement that CodeMirror itself guarantees; what is worth testing is
the conversion, and that has its own 72 cases on both engines.

## What this does not do

- **Tables.** Design 4.5 also lists cell navigation and row and column
  commands. Those came with the table widget in WP 0.4 and are not
  touched here.
- **Multiple cursors.** `markEdit` marks every range because that is how
  a CodeMirror command is written, but `allowMultipleSelections` is off,
  so there is only ever one.
- **Find in Read mode.** Cmd+F there switches to Edit. Reading-mode
  search belongs with the workspace search in Phase 2.
- **Smart typography.** Off, as design 4.5 says, and `autocorrect` and
  `autocapitalize` are off with it: what the model wrote is what it
  meant, and an editor that substitutes characters while you type breaks
  the promise the app makes about bytes.

## Consequences

- `@codemirror/search` is a new dependency of `@mdreader/editor-core`,
  and `base64` a new one of `mdreader-app`. Both are small and neither
  was already avoidable.
- `AnnotationEdit` is now an alias of a shared `Edit` in
  `commands/edit.ts`; the annotation commands and the format commands
  plan the same shape and share one `command` wrapper.
- Two new IPC commands, `write_asset` and `import_asset`, both of which
  widen the asset protocol scope to the document's folder. A document
  saved for the first time is now told to as well, or an image pasted
  into it would not draw.
- macOS spell check needs one thing the app cannot set: see the
  by-hand note.
