# ADR 0006: WP 1.1 file IO with metadata

Status: accepted, 2026-09-08. Covers `crates/core/src/{document,eol,atomic}.rs`
and the app commands `open_document`, `save_document`,
`convert_document_to_utf8`.

## The contract

`open_document(path)` returns the decoded content and a `DocumentMeta`:
byte length, mtime, BLAKE3 hash of the disk bytes, `read_only`, and a
`FileFormat` with the dominant line ending, whether endings are mixed,
BOM presence, trailing newline presence, and the encoding label.

`save_document(path, content, expected_hash, format)` takes the editor's
buffer and the format the app got on open (or a changed one, when the
user asked for a change), refuses with `hash_mismatch` when the file on
disk no longer has `expected_hash`, encodes the buffer back into the
stored form, and replaces the file atomically. A missing file with a
hash presented is recreated: that is the tab whose file was deleted
under it. Errors are a tagged enum serialized with `kind`, so the
frontend branches without parsing messages.

## Line endings are restored per line, not per file

The editor normalizes every ending to LF on load. A file that mixes
CRLF and LF would come back uniform if the save applied one style, a
byte change the user never made. The save therefore reads the file on
disk (it does so anyway for the hash check), aligns the buffer's lines
to the disk's with a line diff (`similar`), and gives every surviving
line the ending it had. A line edited in place is paired with the line
it replaced and keeps that ending; a wholly new line gets the dominant
style. The property test writes random mixes of endings, BOM, and
trailing newline and checks open then save is the identity; the
integration test does the same over every adversarial corpus file
through the real path, then makes one edit and checks that only that
byte differs. `mixed-eol.md` passes both.

`trailing_newline` restores in one direction: a missing terminator is
appended when the file had one, a present one is never removed. A BOM
is stripped on read and re-added on write; the corpus test in WP 0.5
showed the editor would also have kept it as U+FEFF, but stripping it
keeps the buffer clean for the parser and the annotations.

## Encoding

UTF-8 is the fast path. Anything else goes through `chardetng` and
`encoding_rs`, is returned decoded with `read_only: true` and the
label, and cannot be saved; `convert_document_to_utf8` rewrites the file
as UTF-8 on request and is the one command that changes bytes the user
did not type. `blake3` is built with its `pure` feature so the crate
cross-compiles for Windows from a Mac without a C toolchain; hashing a
megabyte in portable Rust takes a few milliseconds and happens on open
and save only.

## Atomic replacement

Write to a temporary file in the target's directory, `fsync`, copy the
target's permission bits, swap, `fsync` the directory. On Unix the swap
is `rename`. On Windows it is `ReplaceFileW`, because `rename` there is
`MoveFileExW`, which gives the target the temporary file's ACL; sharing
and lock violations from indexers and sync clients are retried with
backoff up to about two seconds, and a missing target falls back to
`rename`. That call is the crate's only `unsafe`, allowed for that
module alone under a workspace-wide deny. The Windows-only retry test
opens the target with an exclusive share mode from another thread and
saves through it. It compiles under `cargo check --target
x86_64-pc-windows-msvc` from this Mac but has not run on Windows;
CI's Windows job will run it when the repository has a remote.

## App

The desktop shell's debug save is gone. Save presents the hash and the
format from open, updates them from the result, shows the format in the
status bar, and offers Convert to UTF-8 for a read-only document. The
frontend bindings are still hand-written; WP 1.2 generates them.
