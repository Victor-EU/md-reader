# ADR 0001: WP 0.1 skeleton decisions

Status: accepted, 2026-09-07. Companion to build plan section 3, WP 0.1.

Interpretations made while building the skeleton, in the order they matter.

## Bundle identifier: `io.github.victor-eu.mdreader`

Reverse-DNS under a domain the author controls: the GitHub Pages domain of
the `Victor-EU` account. Hyphens are legal in Apple bundle identifiers and in
Tauri's validation; underscores are not legal on Apple, which rules out the
Flatpak-style `victor_eu`. The last segment uses the working title on purpose:
the plan accepts that the product name changes while the identifier does not.

Nothing has shipped, so this is still cheap to change until the first dogfood
build (WP 1.12). After that it is baked into file associations, the updater,
and app data paths.

## License: not yet chosen

The plan asks for the license in WP 0.1 because the corpus (WP 0.5) is
committed under it. No `LICENSE` file exists yet; a placeholder would be
worse than none. This must be settled before the first corpus file lands.

## Toolchain pins

| Tool | Pin | Why |
|---|---|---|
| Rust | `1.98.1` via `rust-toolchain.toml` | Workspace lints deny warnings; a floating channel would break the build on every new rustc lint |
| TypeScript | `~5.9.3` | TypeScript 7 (the native compiler) is current, but `svelte-check` 4.7 accepts only 5.x and 6.x |
| CodeMirror, Lezer | tilde ranges | Plan 1.2: pin minor versions, upgrade deliberately |
| Vitest | `5.0.0` with `@vitest/browser-playwright` | Browser mode on Chromium and WebKit from day one, so the corpus runner in WP 0.5 has a home |
| Biome | `2.5.12` | Svelte files: unused-variable rules are off because Biome cannot see template usage; `svelte-check` covers them |

## Line endings in WP 0.1

CodeMirror normalises CRLF to LF when a document is loaded, and the plan
already assigns line ending identity to the Rust path in WP 1.1. So in WP 0.1
the Rust read returns exact bytes, the editor holds LF text, and the debug
save writes whatever the editor holds. A CRLF file saved with the debug button
comes back as LF. This is the documented gap that WP 1.1 closes; the editor
test `state.test.ts` pins the current behaviour so it cannot go unnoticed.

## Plugin permissions and the crate split

Tauri plugins expose their permission set to `tauri-build` through Cargo
`links` metadata, which only reaches direct dependents. The plugin is
therefore listed as a dependency of both `crates/app` (which registers it)
and `apps/desktop/src-tauri` (which runs `tauri-build`). Every future plugin
follows the same rule.

## Command arguments

`#[tauri::command]` functions take owned arguments because the IPC
deserializer produces owned values. Clippy pedantic's
`needless_pass_by_value` is allowed for the `crates/app` crate only.

## CI

`check` and `test` run on every push and pull request on macos-14,
windows-2022, ubuntu-24.04. `build` runs on main, on `v*` tags, nightly, and
on demand, and uploads the unsigned bundles. The `bench` job waits for the
bench harness (WP 0.3) and the two pinned machines. The workflow has not yet
run: the repository has no remote at the time of writing.

## What is stubbed

- Windows `browserAcceleratorKeys: false` (plan section 8) lands with the
  command registry in WP 1.3, so that devtools and reload keep working during
  Phase 0.
- macOS universal binary and Windows arm64 targets come with WP 1.12; the
  build job produces host-architecture bundles until then.
- The icon is a generated placeholder (`icons/source.png`); regenerate with
  `pnpm --filter @mdreader/desktop exec tauri icon src-tauri/icons/source.png -o src-tauri/icons`.
