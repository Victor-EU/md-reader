# ADR 0005: WP 0.5 the round-trip corpus test

Status: accepted, 2026-09-08. Covers `packages/editor-core/src/corpus`,
`corpus/`, and `tools/corpus-gen`.

## What runs today

The harness from design section 10: for every corpus file and every
action in the Phase 0 catalog, plan an edit, perform it through the
editor's real command, and check three invariants. Seeded per (file,
action), so a failure prints the file, the action, its seed, the plan,
and the byte diff, and is reproducible on its own.

- **A. Exactness.** The document after the command equals the expected
  change set applied to the one before. The expected change is computed
  from the source text without the editor.
- **B. Locality.** Outside the top-level blocks the change touched, the
  parse tree is structurally identical before and after, positions
  shifted by the change. A change in the gap between two blocks counts
  both neighbours as touched.
- **C. Identity.** Loading and reading back is byte identical. LF files
  pass. A BOM survives as U+FEFF in the buffer, so BOM-only files pass
  too. CRLF is normalized by CodeMirror, so the three CRLF files are
  listed as deferred to the Rust path (WP 1.1); the test asserts that
  list so a change in either direction is noticed.

Actions in the Node runner: type a character, delete a character, toggle
a checkbox, edit a table cell (the rebase and escaping half), press
Enter in a list item, wrap a selection in bold, wrap in highlight,
insert a comment after a selection. Actions in the browser runner: edit
a table cell through the nested editor, and an IME composition in a
paragraph, on Chromium and WebKit.

Corpus: 37 hand-written adversarial files under `corpus/adversarial`
(CRLF, BOM, mixed EOL, tabs, unclosed fences, ragged and escaped tables,
mixed list markers, trailing spaces, no final newline, indented code,
HTML fragments, deep nesting, setext, callouts, math, comments,
frontmatter, empty, long lines, Unicode, links, emphasis edges, lazy
quotes, tasks, rules, Windows paths, code and tables in containers,
whitespace-only lines, heading links, large numbers), plus 200
deterministic synthetic documents from `generateDocument` in the Node
run and 24 in the browser run. The Node run takes about five seconds,
the browser run under three per engine, well inside the plan's budgets.

## What the corpus found before the first generated file

`@codemirror/lang-markdown`'s `insertNewlineContinueMarkup`, which WP
0.1 had bound to Enter, does four things beyond continuing the marker:
it trims trailing whitespace on the current line, which destroys a
two-space hard break; it converts tab indentation to spaces; it inserts
a blank line when the list is loose; and it renumbers ordered items.
Each one is a byte change the user did not ask for. The editor now
binds its own `insertNewlineMarkdown`: it copies the line's quote and
list markup byte for byte, bumps only the current number, unchecks a
task, steps out of a list or quote on an empty item, copies plain
indentation without trimming, and never touches another line. Its plan
function is what the corpus expects, so the command and the expectation
share one definition. lang-markdown's Backspace over a marker is kept.

## Corpus generation is a person's job

`tools/corpus-gen/generate.mjs` calls a model API with prompts per
document category, asks for the constructs the dialect supports, tells
the model to invent everything and quote nothing, and records model,
category, prompt hash, date, and size in `corpus/generated/manifest.json`.
It has not been run: it costs money, needs keys, and generated text is
committed under the repository license, which is not chosen yet. The
synthetic set gives the harness volume until then; it is not a
substitute for model output, whose quirks are the point.
