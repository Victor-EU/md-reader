# ADR 0003: WP 0.3 live preview for the common blocks

Status: accepted, 2026-09-07. Covers `packages/editor-core` and
`tools/bench` after WP 0.3.

## The tree field is CodeMirror's

The plan asks for "a StateField holding the tree, updated incrementally".
`@codemirror/language` already keeps exactly that field and updates it
incrementally on every transaction; `syntaxTree(state)` reads it. A second
field would hold a second copy of the same tree, so there is none. The
plugin notices a tree change by comparing `syntaxTree(update.state)` with
`syntaxTree(update.startState)`, which also covers the background parse
finishing a chunk with no document change.

## The reveal rule is one pure function

`revealRanges(state)` maps the selection and the tree to the ranges whose
syntax is shown, and nothing else decides that. Its rules:

- A selection touches a node when they overlap or a cursor sits at either
  edge. Lezer's `iterate` visits exactly those nodes.
- Inline units are the outermost formatting element touched: Emphasis,
  StrongEmphasis, InlineCode, Link, Image, Autolink, Highlight,
  Strikethrough, InlineMath, Escape. Nested marks inside a revealed unit
  are all shown, because hiding the outer `**` while the inner `*` is open
  makes edits at the boundary guesswork.
- Block units are headings, fences, indented code, block math,
  frontmatter, tables, HTML and comment blocks, and horizontal rules. A
  heading is walked into for its inline units; a fence is not.
- Bullets, checkboxes, and blockquote markers are not units. Bullets and
  checkboxes are always widgets and the cursor skips them through
  `EditorView.atomicRanges`; the `>` of a quote is never hidden, only
  dimmed, which is why the Enter key can still continue it.

Each reveal range carries `block: true | false`, and a hidden mark checks
only ranges of its own kind. The cursor on a heading line therefore shows
the `#` but not the `**` further along the line, until it reaches them.

## Decorations are built by a pure function too

`buildDecorations(state, ranges, reveal)` walks the tree over the given
ranges and returns plain decoration ranges. The view plugin calls it with
`view.visibleRanges`; the snapshot tests call it with the whole document
in Node, one `.decorations` file per parser fixture. What it emits:

| Construct | Decoration |
|---|---|
| ATX heading | line class `mdr-hN`; `# ` and any closing marks hidden |
| Setext heading | line class on the content lines; the underline dimmed |
| Emphasis, strong, code, link, highlight, strikethrough, inline math | mark class on the element; delimiters, URLs, titles, and labels hidden |
| Escape | the backslash hidden |
| Bullet list item | `- ` replaced by a bullet widget, atomic |
| Task item | `- ` hidden, `[ ] ` replaced by a checkbox widget, atomic |
| Ordered list item | marker visible, muted |
| Any list item | hanging indent by the marker width, on the item's own lines only |
| Blockquote | line class with a left border; the callout variant carries `data-callout` and a header line class |
| Fenced code | line class per line; the two fence lines dimmed, undimmed while the cursor is inside |
| Block math, frontmatter, table, HTML and comment blocks, rules | line class; marks dimmed |

Hidden syntax inside a revealed unit is shown with the `mdr-syntax` class
rather than removed from the decoration set, so a revealed heading still
reads as a heading with a faint `#`.

## Widgets dispatch, they do not edit the DOM

The checkbox toggles by dispatching a one-character change to the marker
found at `view.posAtDOM(input)`. That is the byte diff the round-trip
corpus expects from a checkbox action (WP 0.5), and it is the small
version of the pattern the table widget will use: the widget knows
nothing about positions until it asks the view.

## Modes

Edit and Source are a `Compartment`: Source removes the plugin and the
theme and keeps the buffer, history, and selection. `Editor.setMode` on
the public API; the desktop app has a toggle button so the decorations
can be dogfooded immediately.

## Base language is CommonMark plus the dialect

Carried over from ADR 0002: the editor's parser is `commonmarkLanguage`
plus `@mdreader/markdown`'s extension list, with the table folding rule
from lang-markdown's GFM bundle re-added. Syntax colours for fences and
Source mode come from one `HighlightStyle` whose markdown rules say the
same things as the preview classes (bold headings, italic emphasis).

## Bench harness and numbers

`tools/bench` is a Vitest browser project excluded from `pnpm test` and
run by `pnpm bench`. It generates deterministic synthetic documents of a
given byte size with a realistic block mix, mounts the editor in a 600 px
viewport, and measures 200 keystrokes at the start, middle, and end. The
budgeted number is the synchronous work per keystroke: dispatch plus a
forced layout. Time to the next animation frame is recorded but sits on
the 16.7 ms vsync interval in a headless browser and says nothing about
the work. Results are written to `tools/bench/results/keystroke-<browser>.json`
(ignored by git).

Measured on 2026-09-07, MacBook arm64, Playwright Chromium and WebKit,
work per keystroke in milliseconds:

| Size | Position | Chromium p50 / p95 / max | WebKit p50 / p95 / max |
|---|---|---|---|
| 100 KB | start | 1.2 / 2.1 / 3.9 | 2 / 2 / 6 |
| 100 KB | middle | 1.4 / 1.8 / 4.5 | 2 / 2 / 3 |
| 100 KB | end | 1.4 / 1.8 / 2.2 | 2 / 2 / 3 |
| 1 MB | start | 4.9 / 6.1 / 12 | 4 / 6 / 8 |
| 1 MB | middle | 7.1 / 7.9 / 25.4 | 6 / 8 / 32 |
| 1 MB | end | 3.3 / 4.1 / 24.1 | 4 / 6 / 28 |

Under the 16 ms p95 budget in both browsers. Two things to watch: the
per-keystroke cost grows with document size even though the decoration
rebuild is viewport-bound, which points at fragment reuse in the
incremental parse being linear in the number of blocks before the edit;
and the max values at 1 MB are single spikes, most likely a background
parse chunk or garbage collection landing on a keystroke. Neither needs
action for the Phase 0 gate; both are noted for the WKWebView and
WebView2 numbers in WP 0.7.

## Deferred

Block widgets for tables (WP 0.4), math, Mermaid, images, and
frontmatter (Phase 1). Comment rendering in the margin. The hanging
indent uses `ch` units against a proportional font and is close, not
exact; the theme work package owns that. Click on a link. Reveal for a
non-empty selection shows every unit it overlaps, which matches Obsidian;
a future refinement could keep marks hidden inside a selection that only
passes through an element.
